## 0. 结论摘要(先给结论)

**cn23154 的 0xd22 die 上、物理核 145(逻辑 CPU 139,package 0 / NUMA 3 / module 3)存在间歇性、微架构层面的静默数据损坏(SDC)缺陷**,在约 16 分钟的连续压测中产生两类可复现的硬件故障表现:

1. **数值 SDC(12 次)**:全部由 `memcmp` 字节级比对捕获;字节级取证证明 **12/12 次损坏全部发生在 test_init(黄金值计算)一侧**,运行侧(test_run)输出在同种子组内逐字节恒定。损坏的数学签名是 **BDCSVD computeSingVecs 列归一化路径中单个 double 标量的损坏**经线性传播放大为整列/列区间的恒定比例缩放:
   - 最小签名:单一输出列、299/300 元素、**比值精确恒定**(FAIL8 col 38 比值 24145.491339,598 个分量偏差 ≤ 2.7e-10;FAIL9 U col 234 全 300 元素**精确 ×2⁻¹⁵**,纯指数位翻转);
   - 最大签名:205 列 / 61295 元素(D&C 分治依赖链整体改写);
   - 共同结构特征:**V 的第 0 行在所有损坏列中逐字节免疫**(V(0,k) 不经过被污染的归一化除数)。
2. **SIGSEGV(1 次)**:发生在同一物理核上、同一测试的黄金值计算时段(两次数值失败之间),寄存器 x20 在**架构空闲窗口**(函数入口 `mov x20, x3` 后 0x11C 字节 = 71 个指令槽、1 次嵌套调用、零次写入、零次读取,直到 `stp d8, d0, [x20]` 首次使用)被翻转 **bits 55:48 共 4 位**(0x00→0x95),FAR = 被污染的 x20,SEGV_MAPERR。**位级重构进一步证明:崩溃时全部 31 个浮点寄存器构成一次完整、自洽、正确的 `real_2x2_jacobi_svd` 计算(v10=u=0.007785677497599682 → rot1.s/c 位精确 → j_left = 完美 90° 旋转,残差 2⁻⁶⁰),没有任何 FP 寄存器损坏——损坏的架构状态只有 x20 一个、4 个位**。这是**寄存器堆/物理寄存器文件(PRF)级**的直接损坏证据,与数值 SDC 同核、同时段、同代码路径(SVE 定长 128-bit 向量后端独占)。

**触发条件画像:** 单核(taskset 139)、定频 2.0 GHz、SVE 路径(NEON 孪生测试 36/36 全过)、复数双精度 BDCSVD 负载。故障率随压测时间**急剧上升**(S1 4.8% → S2 36.4% → S3 27.3%+SIGSEGV → S4 观测 5/5 连败后控制台失联),呈**磨损/劣化型(wear-out)时间特征**,而非稳态随机翻转。

**根因判定(微架构层级):** 同一物理核上同时出现 (a) 单个 double 的位级损坏(含纯指数位翻转)、(b) 架构空闲寄存器 x20 的 4 位翻转、且崩溃时 **FP 寄存器组 100% 完好**(§6.5 第 4 条:唯一损坏的架构状态就是 x20 本身),全部命中同一 SVE 定长向量代码路径,排除软件确定性缺陷(同种子 20 次重跑全过、NEON 路径干净)与内存/互连故障(mce_check 32/32 pass,损坏均为计算数据而非访存通路)。**load/store 通路(LSU,含 store buffer/load 转发旁路,即 CORE179 排查流程 E)已用六项微架构判别排除为故障载体**(§7.4:FAIL9 整列算术 ×2⁻¹⁵ 缩放与逐元素 LSU 损坏机制性矛盾;损坏标量 z 累加器不经内存;位翻转签名非异值替换;12/12 黄金值侧偏置 P=1/4096;同窗 GEMM/sparse 全绿——末项限 NEON 编译边界)。**最可能的硬件层级是 0xd22 核 145 的物理寄存器文件(PRF)位单元的间歇性失效——PRF 位腐坏同时解释数值 SDC(存活于 PRF 的中间 double 被污染,如归一化除数)与 x20 空闲窗口翻转(PRF 中长存活指针条目被污染),且与"FP 计算结果完全正确"的崩溃现场不矛盾(x20 的损坏发生在其 71 指令槽空闲期内,与 FP 通路的正确性正交)**;次要可能是 SVE 定长向量 ALU 的位级翻转。判定依据与备择假设排除见 §7-§9。

## 2. 测试架构与比对语义(取证的前提)

`tests/cpu/eigen_svd/sandstone_eigen_common.h`(EigenSVDTest 模板,实测源码):

```cpp
static int init(struct test *test) {              // 每个 fork 子进程内执行
    d->orig_matrix = Mat::Random(Dim, Dim);       // 300×300 complex<double>,4 draws/元素
    calculate_once(d->orig_matrix, d->u_matrix, d->v_matrix);   // 黄金值 SVD
}
static int run(struct test *test, int) {          // 工作线程(test_run)
    do {
        calculate_once(d->orig_matrix, u, v);     // 同一 orig_matrix 重新计算
        compare_or_fail(u.data(), d->u_matrix.data(), "Matrix U");   // 先 U
        compare_or_fail(v.data(), d->v_matrix.data(), "Matrix V");   // 后 V
    } while (test_time_condition(test));
}
```

- `calculate_once` = `BDCSVD<Matrix<complex<double>,300,300>>(orig, ComputeFullU|ComputeFullV)`(`m_algoswap=16` → 基例进入内部 JacobiSVD → `real_2x2_jacobi_svd`)。
- 比对是**字节精确 memcmp**;`--max-logdata 0` → `UINT_MAX` → 失败时**全缓冲区转储**(actual = run 侧,expected = init 侧黄金值),每份数据 300×300×16 = 1,440,000 字节,元素 k = (行 k%300, 列 k/300),16 字节 = LE double re + LE double im(列主序)。
- `-Y -F`:失败后同种子重跑;每次迭代都是**新的 fork 子进程**,test_init 在子进程内重新计算黄金值 → 黄金值逐次独立重算(这是 §4.2 黄金值侧归因的架构基础)。
- RNG 语义(用于种子组归组):`Mat::Random` 每元素 4 次 minstd_rand/AES 抽取,复数 re 先 im 后;种子记录于 `fail:` 行。

**反汇编锚点**(二进制 sdcshield+0x1e9b30 起,前次会话对 stripped 二进制的完整反汇编结论,与本次日志 Code-around-RIP 字节码交叉验证):

```
0x1e9b30:  mov  x20, x3              ; 入口: x3 = &j_left(第4参数)
   ...     0x11C 字节 = 71 个指令槽、1 次 call、期间对 x20 零次写入 ...
0x1e9c3c:  4 条标量 double FP 运算(FMUL/FDIV 族,D0/D1/D8/D2/D9)   ; 计算 rot1 分量
0x1e9c4c:  stp  d8, d0, [x20]        ; 首次写 *x20 —— 崩溃指令
0x1e9c50:  ldr  x1, [sp, #56] ; ldr x2, [x0] ; sub x1, x1, x2
```

崩溃窗口字节码(日志 Code around RIP,0xaaaaeaaf9c3c–c58,小端解码):`88 02 00 6d` = `STP D8, D0, [X20]`(0x6d000288);`e1 1f 40 f9` = `LDR X1,[SP,#56]`;`02 00 40 f9` = `LDR X2,[X0]`;`21 00 02 eb` = `SUB X1,X1,X2`。与 `real_2x2_jacobi_svd` 源码(`RealSvd2x2.h:22-43`:u=t/d; tmp=√(1+u²); s=1/tmp; c=u/tmp; `*j_left = rot1 * j_right.transpose()`)的出口序列吻合。

**关键内存布局事实:`JacobiRotation` 的成员声明为 `Scalar m_c, m_s;`**(`third-party/eigen5/Eigen/src/Jacobi/Jacobi.h:82`),故 `m_c` 位于 offset 0、`m_s` 位于 offset 8。因此崩溃指令 `stp d8, d0, [x20]` 的语义是 **d8 → j_left.m_c(offset 0),d0 → j_left.m_s(offset 8)**:待写入的 j_left 是一个 **(c ≈ 0, s = 1+1ULP) 的 90° 旋转**,即本函数出口 `*j_left = rot1 * j_right.transpose()` 的完整位级重构结果(逐寄存器推导见 §6.2–§6.5:d8 = j_left.c = -8.497464257699151e-19 = -sin(2⁻⁶⁰),d0 = j_left.s = 1.0000000000000002 = 1+2⁻⁵²;崩溃时 **全部浮点寄存器状态构成一次完整、自洽、正确的计算,无一损坏**;唯一损坏的只有 x20 指针)。

## 3. 故障隔离(第一层:只有这一个测试失败)

4 个 session 的 live 控制台总计 **1843 条测试条目:1830 pass / 12 fail / 1 crash**(对日志 `  result: ` 行的两遍独立统计:pass=1830、fail=12、crash=1,1830+12+1=1843 ✓),失败与崩溃 **100% 集中于 `eigen_svd_cdouble_sve`**,且线程 id 行全部为 logical 139 / core 145 / module 3 / package 0:

| 测试 | pass | fail | crash | 说明 |
|---|---|---|---|---|
| **eigen_svd_cdouble_sve** | **67** | **12** | **1** | SVE 定长128-bit 后端 |
| eigen_svd_cdouble(NEON 孪生,同算法) | 36 | 0 | 0 | **同算法同精度,NEON 路径干净** |
| eigen_svd_cdouble_noavx512 | 36 | 0 | 0 | |
| eigen_svd / svd_double / svd_double2 / svd_fvectors | 132/36/131/145 | 0 | 0 | 实数 SVD 家族 |
| eigen_gemm_*(7 个变体) | 1178 | 0 | 0 | GEMM 家族(含 SVE 编译单元中运行的负载) |
| eigen_sparse | 36 | 0 | 0 | 稀疏 Cholesky |
| mce_check | 32 | 0 | 0 | EDAC CE/UE 计数无事件 |

关键推理:
- **NEON 孪生 36/36 全过** → 排除"complex<double> BDCSVD 算法/数值边界/种子数据"类软件缺陷(若是软件 bug,NEON 路径同种子同样数据也必失败);
- **SVE 路径独占失败** → 缺陷与 SVE 指令语义执行路径(定长 128-bit SVE 指令)强相关;
- **全部失败线程 = 同一物理核 145** → 单核缺陷,非系统级(内存/互连/供电轨)故障;
- **同种子失败 + 同种子重跑通过共存**(见 §4)→ 间歇性硬件故障,非确定性软件缺陷。

## 5. 数值 SDC 的微架构签名(第三层:损坏如何传播)

### 5.1 三级签名谱系(全部字节级实测)

**签名 A — 单列精确恒定缩放(最小可分辨签名,FAIL8/FAIL9/FAIL5 部分)**

- FAIL8 col 38:全 299 行、re/im 共 598 个分量,actual/golden 比值 = 24145.491339,**散布 ≤ 2.7e-10 相对**(即黄金列 = 正确列 × 1/24145.491339,残差仅为除法/舍入噪声);col 39 比值 = 0.2483765947,散布 ≤ 2.1e-10;col 11 比值 ≈ 5997.175,散布 ~1e-7(近缩放,含二次效应)。
- FAIL9 U col 234:全 **300/300** 元素(含行 0)**精确 ×2⁻¹⁵**(逐元素验证 actual = golden × 2⁻¹⁵,无一个例外)——**纯指数域损坏**。

104–205 个不连续列(部分成段,如 FAIL1 的 174-299 连续段)、每列恰好 299/300 行不同。BDCSVD 分治(divide & conquer)中,`computeSingVecs` 的每一列都依赖 `diag/perm/shifts/mus/singVals` 公共数组与 D&C 递归的中间量;污染 D&C 早期的一个 double(如 `perturbCol0`/`divide` 中的标量)会经依赖链传播到整段子树列。签名 B = 签名 A 的上游放大。

**签名 C — 首错行恒为行 1、行 0 免疫**

### 6.2 位精确重构链(从崩溃寄存器值反推 `real_2x2_jacobi_svd` 的完整执行)

对照源码 `RealSvd2x2.h:22-43` 逐步重构(全部为实测位模式的精确算术,非估计):

```
t  = m00 + m11 = ±1.8109140734332816      (v11 = |t|)
u  = t/d       = 0.007785677497599682     (v10)
```

- **j_right = (c=v1, s=v9)**,即 `makeJacobi` 作用于 applyOnTheLeft 后的 2×2 实矩阵的输出,旋转角 θ_right = atan2(v9,v1) = **0.446077448°**(实测)。
- **θ_rot1 + θ_right = atan2(1,u) + atan2(u,1) = 90.000000000°(精确)**——这是对任意 u 成立的数学恒等式(atan2(1,u)+atan2(u,1)=π/2,u>0),说明 j_right 与 rot1 结构互补:复数 2×2 块经 `svd_precondition_2x2_block_to_be_real` 化实后,j_right 恰好补齐 rot1 到 90°。**这是寄存器状态自洽性的数学闭环证明。**
- **j_left = rot1 × j_rightᵀ**(源码出口):实测 d8 = -8.497464257699151e-19 = -sin(eps),eps = 2⁻⁶⁰·⁰³;d0 = 1.0000000000000002 = 1+1ULP(d0-1 = 2⁻⁵²,即最低位 1)。即 **j_left 是一个数学上完美的 90° 旋转:cos≈0(残差 2⁻⁶⁰)、sin=1+1ULP**——2×2 块被精确对角化为互为转置的一对 90°/0.446° 旋转的乘积。
- **makeJacobi 内部量重构的一个未闭合细节(诚实声明):** Eigen 的 `makeJacobi`(`Jacobi.h:93-113`)从旋转后矩阵的 (x,y,z)=(m00′,m01′,m11′) 计算 τ=(x−z)/(2|y|)、w=√(τ²+1)、t=1/(τ±w),再得 c=n、s=−sign(t)·sign(y)·|t|·n(n=1/√(t²+1))。崩溃寄存器中未保留可无歧义对应 (x−z)/2|y| 的分量(§6.1 中标注"未定位语义"的寄存器不强行归因),复核脚本(`jreg_reconstruct.py`,§10 附录)以 τ=|v9| 为探针给出 1/(τ+w) ≠ v10,属预期性证伪而非矛盾。**这不影响任何已证实的位级关系**(v9/v1=v10 位精确、角度和恒等式精确、d8/d0 语义明确)——v10 = v9/v1 已直接从寄存器位模式独立验证(数学上 c=s/u 恒成立),无需经由 makeJacobi 的闭式公式;此处差异仅表明 makeJacobi 的输入 m′(经 applyOnTheLeft 旋转后的矩阵)与原始 (t,d) 分量间存在多步中间运算,已如实记录,不做臆测。

| **崩溃时 FP 状态 100% 正确** | v10→v1/v9→j_left 位精确重构,残差 2⁻⁶⁰ | **损坏载体收窄到 x20 的 PRF 条目**(计算通路未被污染) |
| 时间演化 | 4.8% → 36.4% → 27.3%+崩溃 → 5/5 连败 → 节点失联 | 劣化型(wear-out) |
| 无 CE/UE | mce_check 32/32 pass | 内存通路未见错误 |

### 7.2 备择假设逐一排除

1. **"Eigen SVE 后端软件 bug"** — 证伪:同种子 20 次重跑(S1)全过;同一二进制 80 次运行 67 次过;NEON 孪生同算法全过;损坏签名(恒定比例缩放、×2⁻¹⁵)不是浮点语义错误的形状,是位损坏的形状。软件 bug 不会翻转架构空闲寄存器的 4 个位。
2. **"种子/数据边界触发"** — 证伪:同一失败种子(如 LCG:300065116)既有 5 连败也有(其他 session 中同种子家族)通过;种子组不同(2 个 AES + 2 个 LCG)但故障模式相同;actual 侧同种子逐字节恒定说明输入数据可完全复算。
3. **"内存/DIMM/互连 ECC 故障"** — 排除为主因:mce_check 无 CE/UE 计数;损坏仅命中 SVE 计算数据与一个指针寄存器,未命中同进程其他 100 万+ 字节结构(转储其余部分、orig_matrix、框架数据全好);PRF 空闲翻转不是内存通路的物理表现。
4. **"热/供电引起的核间共性故障"** — 排除:仅核 145,同 package 同 module 的其他核(整个 eigen* 全测试在 139 上跑,但同机其他核未运行本测试——此条为**弱排除**,受限于单核压测设计;但 taskset 独占 139 而集群 isolcpus 使其他核空闲,S3/S4 的 36%/27%/100% 失败率若为共性因素应同样打击 608 核上任何负载,与"节点此后整体失联"边界一致,需后续多核对照实验)。
5. **"SVE 定长 128-bit 模式的架构性软件问题"** — 证伪:`-msve-vector-bits=128` 生成的 SVE 指令在 512-bit 硬件上运行是标准支持组合;同为 SVE 定长 128-bit 编译单元内的其他负载(eigen_gemm SVE 变体、eigen_sparse 等在本二进制中同条件构建)全部通过;但注意:**gemm 等测试的指令混合与 SVD 不同,此排除仅到"指令组合特异性"层级**——缺陷可能正是 SVD 路径特有的 SVE 指令序列(标量 FP + SVE gather/归一化混合)在核 145 上的微架构定时/老化问题。
6. **"load/store 通路故障(store buffer 旁路 / load 转发 / LSU 数据通路位翻转,CORE179 流程 E 家族)"** — 排除为故障载体:六项独立判别(FAIL9 整列算术 ×2⁻¹⁵ vs 逐元素损坏的机制性矛盾、单元素不可能界、损坏标量 z 不经内存、位翻转非异值替换签名、12/12 黄金值侧偏置 P=1/4096、同窗 LSU 压力负载全绿[限 NEON 编译边界])全部与 LSU 假说矛盾,完整推理与证据强度声明见 **§7.4**。

### 7.3 根因判定(最终)

**物理核 145(0xd22,module 3)的微架构数据通路存在间歇性位级失效,最可能载体为物理寄存器文件(PRF)的位存储单元,其次为 SVE 定长向量/标量混合执行路径上的锁存器。** 判定逻辑:

- x20 事件**只能**发生在 PRF(架构空闲寄存器被改写的唯一物理位置);
- 数值 SDC 的"单个 double 指数/尾数位损坏"与 PRF 中长存活 double 被翻转完全兼容(归一化除数从计算到使用在 PRF 存活数百周期);
- 两类故障同核、同时段、同路径共生,统一解释优于双原因;
- 劣化型时间特征(PRF 位单元老化/阈壅移导致保持/读出错误,随温度和持续活动加剧)与 4.8%→100% 的故障率爬升及最终节点失联一致。

**定位精度声明:** 证据锚定到"物理核 145 的 PRF/执行通路位级失效";PRF vs 执行单元锁存 vs SVE 特定功能单元的最终区分需要 (a) 核 145 vs 相邻核的多核对照压测、(b) PMU/SPE 采样、(c) 故障核的指令级最小复现(MRU)。这些是后续实验(§9),非本报告内已完成的实证。

### 7.4 load/store 通路(LSU)假说的微架构判别(对照 CORE179 流程 E)

CORE179 案例的根因排查六流程(`docs/cases/sdc1-01-02-core179-diagnostics/CORE179_SDC_ROOTCAUSE_REPORT.md` §11.2a)中,流程 E 即"store buffer / load forwarding 旁路"假说——load 通路(含 store→load 转发)把错误数据送入计算。CORE179 靠**损坏形状**将其排除:旁路混叠应注入"邻接的简单值"(如刚清零的 y[0]),而实测是整寄存器"异值替代"(−15.68,一个本不该在此的完整浮点数)。本案用同一方法论、但证据更强(有完整的 45000 对十六进制转储),从四个独立维度判别 LSU 假说。

#### 7.4.1 判别一:整列算术均匀缩放 vs 逐元素位翻转(FAIL9 决定性实验)

FAIL9(U 矩阵 col 234)首错元素 actual=0xbe9725b3d6ad86d1 / expected=0xbf8725b3d6ad86d1:符号位相同、尾数 52 位逐位相同、仅指数域差(0x3f8−0x3e9=15)。逐元素全量验证(`f8divisor2.pl`[600/600 精确 ×2⁻¹⁵]/`f9expdiv2.pl`/`f9xorfinal.pl`,600 个 half 全查):

```
  arithmetic: eg-ea == +15 for all:  ok=600 bad=0   (golden = actual x 2^15)
  mantissa identical: bad=0 ; sign identical: bad=0
  actual(correct) exp&0x11 classes: 0x00:293 0x01:307 0x10:0 0x11:0
  golden(corrupt) exp&0x11 classes: 0x00:0 0x01:1 0x10:307 0x11:292
  fixed-XOR(bits 52/56) predicted shift eg-ea by ACTUAL-exp class:
    0x00 -> +17   0x01 -> +15   0x10 -> +0   0x11 -> +0
  elements CONSISTENT with fixed-XOR (eg == ea^0x11): 307 ; CONTRADICTING: 293
```

**推理链:**
1. **算术均匀性**:600/600 个 half 满足 golden = actual × 2¹⁵ 精确成立(×2 的幂是纯指数移动,尾数无舍入)。正确列(actual)的指数只落在两个类:0x00(293 个,如首错元素虚部 exp 0x3e8)与 0x01(307 个,如首错元素实部 exp 0x3e9,即报错头的 0xbe97…)。若损坏是"存储/加载边界上对每个元素做固定 XOR(翻转位 52/56)":类 0x00(位 0=0、位 4=0)应移 **+17**(两位置 1),类 0x01(位 0=1、位 4=0)应移 +15(翻转恰好等效)。实测:**293 个类 0x00 元素全部 +15**——例如 0x3e8(0b01111101000)+15 = 0x3f7(0b01111110111),低 5 位 01000+01111=10111 需要**从位 3 向位 4 的加法进位**,而 XOR-0x11 给出 0x3f9(+17),与实测矛盾;600/600 一致于 +15 → 损坏是**对整列施加的一个算术标量因子**(按 §5.1 的 k 约定 actual = golden × 2⁻¹⁵,即黄金值列整体被放大 2¹⁵、等价于其归一化除数被缩小 2¹⁵),不是 300 次独立的逐元素位翻转。(类 0x01 的 307 个元素 +15 与 XOR 等价,不构成判别;判别力全部来自类 0x00 的 293 个。)
2. **单元素不可能界**:golden col234 的 z=Σ|xᵢ|²=0.22652905637574997,最大元素平方占比仅 7.76%(`f9norm.pl`)。任何**单元素**损坏(包括 LSU store-to-load 转发转发错一个元素)最多改变 z 约 8%,即 |k−1| ≤ 0.078;实测 k=2⁻¹⁵=3.05e-5,比界小三个数量级 → FAIL9 的损坏**必须**是乘到整列的单个标量(归一化除数 √z 一类),不可能是"加载/存储路径损坏了一个元素"。
3. **损坏标量的寄存器位翻转重构**:z 的位模式 0x3fccfee7745d218d,指数 0x3fc;z÷2³⁰ 的指数 0x3de;0x3fc XOR 0x3de = 0x022(popcount=2,`f9norm2.pl`)——**z 的指数域恰好 2 位翻转即精确产生 ×2⁻¹⁵ 的整列缩放**(÷2 的幂无舍入,尾数逐位保留,与实测 600/600 尾数相同一致)。z 是 squaredNorm 归约的累加器,在 600 元素归约期间是**存于寄存器(物理寄存器文件条目)中的单个 double**,从不经过内存。

**LSU 判别结论:** 若故障在 load/store 通路(store buffer 旁路、load 转发掩体、L1 端口位翻转),损坏应表现为**单个或离散多个元素的位翻转/替换**(数据在 LSU 上按元素粒度流动);实测是**作用于整列的算术标量缩放**,且该标量(normalize 的 z 累加器)在损坏发生时不经内存。FAIL9 在机制上不可由 LSU 故障产生。

#### 7.4.2 判别二:替换 vs 位翻转的签名判别(CORE179 流程 E 判据的镜像应用)

CORE179 用"损坏值是不是邻接的简单值"排除流程 E(旁路→异值注入)。本案判据更细:LSU 旁路类故障的典型损坏形状是**异值替换**(整字或整双字换成另一个来源的值);而位翻转类故障(存储单元位老化)的形状是**原值+若干位翻转,其余位完好**。本案全部损坏签名属后者:

- FAIL9:尾数 52 位 + 符号位全部完好,仅指数 2 位类翻转(进位一致的算术移位);
- FAIL8 col38/39:整列恒定比值 24145.491339(散布 2.7e-10)/0.248376594746(2.1e-10)——比值在 598 个**独立循环迭代**分别算出的元素上恒定,排除了 598 次独立的 LSU 损坏(概率上 598 次同错同量级不可能),指向**同一个上游标量**(归一化除数)被一次损坏;k38·k39/k11=0.99999996 的乘积关系与"两个除数被同一事件污染"自洽;log2 比值 0.559466/−0.009399/0.550067 非 2 的幂 → 与 FAIL9 同为除数损坏,但含尾数位;
- x20 指针:0x0095400021e85830 vs 正确 0x0000400021e85830,XOR=0x0095000000000000(bits 48/50/52/55 共 4 位),**其余 60 位完好且仍指向栈帧附近**——位翻转签名,非异值替换(替换值不可能是"原值翻 4 位"这么巧);
- §6 已证明崩溃时**全部 31 个 FP/SIMD 寄存器构成完整正确的计算**——若 LSU 通路污染数据,正在飞行的 load/store 数据应出现在 v 寄存器中,实测无一损坏。

#### 7.4.3 判别三:黄金值侧 12/12 偏置

12 个 fail 与 1 个 crash 全部 loop-count=0(逐一复核失败条目头,FAIL1–FAIL12 的 `loop-count: 0`),即损坏全部发生在 **test_init 黄金值计算侧**;run 侧在 orig_matrix 上执行**完全相同的 calculate_once、相同的 load/store 指令流**。持续性 LSU 数据通路故障对两侧无偏置:P(12/12 全在一侧 | 无偏置)= 2⁻¹² = 1/4096 = 0.024%(`lsu_sides.pl`)。而 PRF/寄存器存储类故障对 init 侧有真实偏置机制:fork 后首触页、冷缓存/TLB、DVFS 状态切换,init 侧首次执行的特征使长存活寄存器条目暴露于不同的物理应力剖面。

#### 7.4.4 判别四:同窗同核 LSU 压力负载全绿

S3–S4 故障窗口(10:41–10:51)内、同一物理核 139(logical)上的 LSU 最重负载全部通过(`lsu_gemmcount.pl`):eigen_gemm 7 变体 **299 pass / 0 fail**(流式 load/store 密度最高的负载);eigen_sparse **9 pass / 0 fail**(间接寻址 scatter/gather,LSU 事务类型最复杂);eigen_svd 家族(实数)167 pass / 0 fail;mce_check 6 pass(EDAC 无 CE/UE)。**限定(必须如实声明):** `tests_set_sve` 仅含 svd_cdouble_sve.cpp(`tests/cpu/meson.build:393-398`),GEMM/sparse 属 `tests_set_base`、aarch64 下 march_flags 为空(`meson.build:53-110`)→ 它们是 **NEON 编译**的。因此此判别只排除"通用 LSU 数据通路(NEON/SIMD load/store)持续性故障",**不排除**"SVE 特定 load/store 微架构交互"或"特定指令序列触发的瞬时故障"——与 §7.2 第 5 条的排除边界一致。

#### 7.4.5 小结与证据强度声明

| 判别 | 实测 | LSU 假说预测 | 判定 |
|---|---|---|---|
| FAIL9 损坏形状 | 整列 ×2⁻¹⁵ 算术缩放,600/600 尾数完好 | 逐元素位翻转/替换(元素粒度) | **矛盾**(进位传播 XOR 不可产生) |
| 单元素界 | k=3.05e-5 < 界 0.078 三个数量级 | 转发错一个元素 | **矛盾** |
| 损坏标量位置 | z 累加器在寄存器中,不经内存 | LSU 只搬运内存↔寄存器数据 | **矛盾**(载体不在 LSU 可及范围) |
| 替换 vs 翻转 | 全部签名=原值+位翻转 | 旁路类=异值替换 | **矛盾** |
| 侧偏置 | 12/12 golden 侧(P=1/4096) | 两侧无偏置 | **矛盾**(显著性 0.024%) |
| 同窗 LSU 负载 | GEMM 299/0、sparse 9/0 | 持续性 LSU 故障应连带失败 | **矛盾**(限 NEON 编译边界内) |

**结论:load/store 通路不是本案故障的载体(主因),六项判别全部与 LSU 假说矛盾。** 该结论的证据强度:判别一/二是**机制性矛盾**(不是统计排除,是"该机制物理上产生不了该签名");判别三是 0.024% 显著性水平的统计排除;判别四受 SVE-vs-NEON 编译边界限制(序列特异性 LSU 瞬时故障未被此判别覆盖,与 CORE179 报告对"其他负载通过"论证的限定同构)。残余不确定性:故障序列中若存在未被 GEMM/sparse 覆盖的 SVE 特有 load/store 指令模式,无法用现有日志数据完全排除其对 LSU 的牵连——但即便如此,x20 事件(§6.3:71 指令槽 def-use 空闲窗口、零访存、故障 STP 从未到达内存)仍独立地将至少一个损坏锚定在寄存器存储上,LSU 至多只能是并发第二载体而非根因。综合 §7.3:PRF 位级失效(或寄存器存储侧锁存器)仍是唯一与全部 24 份转储 + 寄存器取证自洽的解释。

## 8. 与 CORE179 案例的对照(方法论)

本案例与前作 `docs/cases/sdc1-01-02-core179-diagnostics/`(Kunpeng 920 核 179,2026-08)同为"单核、负载敏感、数值 SDC"家族,但物理签名不同:

| 维度 | CORE179(Kunpeng 920) | 本案(0xd22 核 145) |
|---|---|---|
| 损坏机制 | 乱序引擎寄存器**活性边界泄漏**(混叠进长存活累加器) | **位级翻转**(指数/尾数/指针寄存器多位) |
| 触发条件 | 单核 + 同 socket ≥47 核满载 + N≥256 | 单核即触发,无需满载 |
| 损坏形状 | 固定首元素 x[0],21-32 位混叠 | 整列恒定缩放 / ×2⁻¹⁵ / 列区间改写 / 指针 4 位翻转 |
| 流程 E(LSU/旁路)假说 | 异值替换(−15.68)与旁路注入的"邻接简单值"预测不符 → 排除 | 位翻转签名 + 整列标量缩放 + z 不经内存 + 12/12 侧偏置,六项判别全部矛盾 → 排除(§7.4) |
| 替换 vs 位翻转判别 | **异值替换**(alien value 整字进入) | **原值 + 位翻转**(其余位完好:尾数全保/x20 60 位完好)——正是区分 LSU 旁路与 PRF 位单元的维度 |
| 时间特征 | 稳态可复现(G5:285/285) | 劣化型爬升(4.8%→100%),节点最终失联 |
| 随机性 | 负载确定性触发 | 间歇随机,同种子可过可败 |

两案的共同方法论:严格区分"算法输出结构"与"损坏"(本案零列结构辨析)、黄金值/运行侧归因(fork-per-iteration 架构利用)、单 double 指纹追踪到具体数值构造点(computeSingVecs normalize)。
