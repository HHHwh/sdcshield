      五、微架构诊断

      5.1 崩溃点现场（事实，来自 sdcfault 取证 + objdump 交叉验证）

      25fad4: ldr  x10, [x19, #800]                          ; x10 ← 栈溢出槽 (sp+864)
      25fae8: st1d {za0v.d[w12,0]}, p0, [x9,  xzr, lsl #3]   ; 成功（x9 干净）
      25faf4: st1d {za1v.d[w12,0]}, p0, [x10, xzr, lsl #3]   ; ← 崩溃 PC
      25faf8: st1d {za5v.d[w12,0]}, p0, [x10, x18, lsl #3]   ; 未执行
      25fafc: add  x10, x10, x5                              ; 未执行

      寄存器：x10 = 0x00d74001bd81a180 = uc.far（逐位相等）；x9=0x4001bd811580 干净；x12=0（ZA slice 0，首次迭代）；x18=8；x5=0x1400（步长）；x19=sp+0x40 正常帧指针；x0-x8/x11-x30 全部干净（0x4000/0x4001 合法地址）；pstate=0x80001000；栈窗 sp+0..504 全部干净（psi 面板指针 0x4001bd6f7f00~0x4001bd7ddf00，无任何垃圾）。

      5.2 x10 溯源与 M1/M2 判别（核心未决实验）

      - 故障地址 = x10 原封不动（xzr 索引、lsl #3、偏移 0）→ 排除地址加法器输出损坏；
      - x10 的三个可能损坏点：
        - (a) 溢出存储时数据已坏（M2-store：RF→LSU 存储数据路径）；
        - (b) 槽内数据好、ldr 返回值坏（M2-load：LSU→RF 装载返回路径）；
        - (c) ldr 之后 x10 在寄存器堆/旁路网络中被改写（M1）。
      - 判别实验 A/B'（已设计）：取证栈窗 64→128 qword（覆盖 sp+864 的 [x19,#800] 槽）。槽干净 ⇒ (b)/(c)；槽脏 ⇒ (a)。本次捕获的窗止于 sp+504，差 352 字节未覆盖该槽 —— 这是下一次捕获要补的唯一缺口。
      - 推断（标注为推断）：x10 原值几乎确定为 0x00004001bd81a180 —— 低 48 位落在 psi 面板区，与干净 x9 同页邻域，仅 byte6 被写成 0xd7。

      5.3 si_code=-6 之谜（已解）

      SDCFAULT 捕获的 siginfo 为 si_code=-6（SI_TKILL）、si_addr=0x00006ed2001ea0e1 —— 分解：0x6ed2=28370=suke 的 uid，0x1ea0e1=2007265=崩溃进程 PID，即 SI_TKILL 的 {si_pid, si_uid} 联合体（进程内 raise/tgkill 重发格式）。机制：UCX 错误处理器先收到内核原始投递（故 UCX 独立打印的 0xd74001bd81a180 是真 FAR；backtrace 顶部 libucs+0x2ab7c/+0x29b98 即其日志路径），打印后将信号重发给先前安装的 handler（我们的）——siginfo 被覆盖，ucontext 仍为内核保存的原始故障 pt_regs。

      5.4 证据真实性交叉验证（四条独立证据一致）

      1. uc.pc 处指令字 0xe0ff8142 == objdump 0x25faf4 的 st1d 编码；
      2. uc.far/x10 == UCX 独立打印的故障地址（两条取证路径一致）；
      3. x19=sp+0x40 正常帧指针关系，栈窗内容与程序数据结构吻合；
      4. 单次故障单次捕获（grep 计数：Caught signal ×1、SDCFAULT ×1、end ×1）。

      ⇒ 寄存器证据 100% 真实，不受信号转发机制影响。

      六、关键技术发现

      1. TBI（Top-Byte-Ignore，硬件实证）：当前 boot TCR.TBI0=1 —— byte7（bits 56-63）垃圾解引用成功（硬件忽略），byte6 垃圾仍 fault。推论一：TBI 不解释重启后静默（byte6 在 TBI 下依然崩溃）；推论二：旧 boot 内核报告未掩 byte7（崩溃 #2 显示 byte7=0x25），当前 boot 掩码 —— 早先"bits 62/63 从不损坏”结论受掩码语义污染须重新解读，byte6 窗口（bits 48-61）结论不受影响。
      2. 崩溃点弥散 → 共享地址生成路径缺陷：原始 6 次（laplacian SVE gather/NT-store）+ 本次（syrk SME store），全部是“基址来自 GPR（多经栈溢出槽重载）的向量访存” ⇒ 缺陷不在单个内核，而在共享的装载/地址生成路径 —— 正是 M1/M2 判别的目标。
      3. 频率判别方法学：eigen_solver 计时不可判频（内存受限，差 8-9%）；可靠判据为 sysfs 直读 + xlk 通过数。
