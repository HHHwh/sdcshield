## 变换规范（canonical，源自 P3-P5 已验证形态）

对每个含 `getauxval(AT_HWCAP)` SVE 门控的文件：
1. include 块：`<sys/auxv.h>`/`<asm/hwcap.h>` → `<device/cpu/arm64/arm64_vl.h>`（保留 arm_sve.h；**若文件还探测其他 HWCAP 位如 SVE2/BTI 则保留原 include**）
2. 门控：**仅替换独立的 SVE/VL 子条件**——`getauxval(AT_HWCAP) & HWCAP_SVE` 块 + 其后的 VL 读取/检查 → `const long svl = arm64_require_sve_vl(test, 128, 1024); if (svl < 0) return EXIT_SKIP;`；**复合门**（同文件另有 SVE2/BTI/F32MM 等 HWCAP/HWCAP2 谓词，如 sve512_fmmla/sve2_cross_precision）**不得整条件替换**：保留这些谓词、其本地 skip 分支与非 AArch64 分支，只把纯 SVE 能力 + VL 范围段交给 helper（分流门控，实际执行形态 54b46920/ca4dde86）——事后审计不能替代本约束，SVE-only 主机不得因整条件替换绕过额外能力检查执行不支持的指令。门控替换之外，既有 lanes 换算同步改 `svl/8|svl/4`（**保留原文件已有的范围检查语义——若原文件无范围检查（纯 A 类），补 [2,16]/[4,32] 检查**）
3. run 侧漂移守卫：A 类文件多无守卫——补齐（svcntd/svcntw 对 init 记录值；128 编译 TU 用 arm64_sve_vl_bytes() 防 GCC 折叠——P5 实证教训）
4. SKIP 语义：aarch64 门控的文案/类别统一为 arm64_vl.h canonical（框架签发，正是收敛目的）；非 aarch64 `#else` 分支、资源错误类、占位类保留本地处理，逐个列入 Task 5 例外清单
5. SME 契约（sme_* 文件）：`arm64_require_sme_svl`（HWCAP2_SME 能力 + 128..1024-bit SVL 一次签发）；lanes 换算 svl_bytes/4（f32）、/8（f64）；`smstart sm` → `smstart za` → … → `smstop za` → `smstop sm` 配对生命周期必须保留（P2 裁决形态）

**VL 上限口径**：上限 1024 = 战役四档 gem5 验证口径（spec §7/D1），与 P3-P5 已验证形态一致（实际执行 176 处 `arm64_require_sve_vl` + 3 处 `arm64_require_sme_svl` 调用统一 128..1024，feat/p6-allvl @ a9c1f08c 实测）；`framework/selftest.cpp` 的 128..2048 是 helper 自检语境（全架构域验收），非测试门控口径。A 类文件由无上限收敛为 128..1024 属设计内语义收敛——>1024 档未经本战役验证，诚实 SKIP（文案含实测值）优于未验证执行。**两域并存的已知形态与扩档义务归属**：SVL>1024 的未来硬件（ARM 规范允许至 2048-bit）上将呈现「selftest 全绿（helper 自检域 128..2048）+ SVE/SME 用例全量诚实 SKIP（测试门控域 128..1024）」——这是设计内而非缺陷（SKIP 文案含实测 VL，可经 `--dump-cpu-info`/日志识别）；1024→2048 扩档（门控上限放宽 + gem5 2048 档补证）**归属后续 all-VL 阶段/独立战役**，触发条件 = SVL>1024 真机出现或扩档战役立项，本战役不预设该义务的执行时点，仅在此声明归属以防「绿灯零覆盖」形态无人认领。

**不做的**（明确出界）：不改几何/不改 golden/不改压力语义——P6 是纯探测层迁移；凡发现文件有 VL 相关缺陷（越界/单位错）——**单独 commit + 报告**，不混入机械批（mesh_upi_sve_wide_asymm_read_L3_int 的死脚手架删除不属此列——它是无门控可迁文件的死代码清理，非 VL 缺陷修复；该偏差与「拷贝缺失缺陷单独报告」承诺未兑现均如实入 Task 2 记录与收口清单）。

**验证口径（CLAUDE.md 规则 2 + spec §12.1/§12.2/§12.3/§12.6）**：本机（0xd01，无 SVE/SME）只能验证构建零告警 + SKIP 路径 + selftest——这是**本地边界，不是功能验证**；迁移含 lanes 换算 svl/8|svl/4、漂移守卫、范围检查补齐等**功能行为变更**，功能验收 = gem5-fi 四档（128/256/512/1024-bit）× 16 run 全绿（`SDCSHIELD_FAILS=0`、random checksum 互异，spec §12.1 首条）；zstd19 回归系非 SVE 测试，与迁移面无关联。**§12.2 回归锚逐位一致性的载体**：P6 对 golden/比对逻辑零触碰（680307c4..a9c1f08c diff 中 `memcmp_or_fail`/golden 数据行增删均为 0，实测）；lanes 换算为数学恒等替换（`svl/8`≡`svcntd()`、`svl/4`≡`svcntw()`，36 处换算行实测形态一致）；`SDCSHIELD_FAILS=0` 的机制即每用例内部对 golden 的逐位 memcmp——故「迁移前后逐位一致」= golden 零改动 + 恒等换算 + gem5 补证 `SDCSHIELD_FAILS=0` 三证合一，补证落盘前该链条的运行时环节悬空（与 §12.1 同一缺口，不重复计）。**§12.3 全量 SKIP 实测（2026-10-26 补做，feat/p6-allvl @ 2aa7ecf0 构建，`--quality=-1 --ignore-unknown-tests` 全家族 222 ID）**：SVE/SME 用例 **194/194 干净 SKIP**（skip-category 100% CpuNotSupported；skip-reason 189×'test compiled with sve' + 3×'lrcpc,sve,sve2,sme' + 2×'lrcpc,sve,sve2'，零 fail 零假 pass），其中 P6 迁移面用例 **149/149 全部干净 SKIP**；另 27 个 ID（movbe/neon_add/arm64_sdc 等 NEON·通用 arm64 用例，不依赖 SVE/SME）本机正常 pass，1 个（sve512_fma_arm）在 #288 分支未接线（#294 3b293d9b 接线）不在二进制内。**§12.6 x86-64 零 diff 实测（2026-10-26 补做）**：`git diff --name-only 680307c4 a9c1f08c -- tests/ ':!tests/cpu/sve' ':!tests/cpu/arm64'` = **0 文件**；framework/ 仅 arm64/arm64_vl.h；根 meson.build/meson.options/scripts 零触及；#288 尖端扩展（680307c4..2aa7ecf0）超范围文件仅 CLAUDE.md/README.md（7e464454 纯文档）与 tests/cpu/sleef/sleef_sve.cpp（SVE 文件、物理路径在 sleef/）——x86-64 侧行为文件零触及。**执行状态（诚实记录）**：P6 三批的 gem5 补证因 429 预算中断改主 agent 后台自跑（progress-log 2026-10-24 P6 条目），截至 2026-10-26 未见落盘记录（gem5-fi workloads/sdcshield/ 现有全部 kernel 载体（12 个 *.c + sve_hmac_dual/sve_movbe_kreg_fpcr_dual 目录形态）均为 P2-P5 战役与 #288/#294 修复项载体，无 P6 迁移面全量 kernel；#288 R2/R3 的 12/16-run 矩阵仅覆盖其各自修复文件）——PR #288 人工 merge 门须按 spec §12.1 核验补证；豁免仅限 gem5 验证 **genuinely impossible** 的情形（CLAUDE.md 规则 2 原文前提），429 预算中断属**延期**而非豁免前提，不得以「构建 + SKIP 干净」替代功能验证（CLAUDE.md PR #242 先例）。
