# SDCShield 代码检视上下文（Greptile）

本文件为 Greptile AI 代码检视机器人提供本仓库的评审上下文，重点覆盖**静默数据损坏（Silent Data Corruption, SDC）激发能力**。结构化规则见同目录 `.greptile/config.json`。

## 一、仓库定位

SDCShield 用于检测**静默数据损坏（SDC）**——计算过程不崩溃、不报错，却产出了错误的比特。方法：对计算单元（FMA、SIMD、压缩、SVD、crypto 等）持续施加压力，并将实际结果与**黄金值（golden value）做字节级比较**来发现错误比特。

本仓库是 Intel OpenDCDiag 的 **ARM64 移植**（目标平台 Kunpeng 920 / ARMv8.1+，openEuler）。**x86-64 是未改动的参考架构**，ARM64 移植是增量式、可叠加的；检视时应保护 x86-64 不被回归影响。

一次测试的执行模型：框架把每个测试 fork 到独立子进程，`test_init` 内为各 CPU 派生工作线程调用 `test_run`，父进程通过 `forkfd` 收集结果。测试是位于特殊 ELF `tests` 段中的 `struct test` 实例。

## 二、六条 SDC 检视要点（可读版）

### 1. 激发强度与覆盖
激发（excitation）是发现 SDC 的前提。评审时确认：改动是否真的对目标计算单元施加了**持续且多样**的压力——覆盖不同数据宽度与数据模式（全 0、全 1、随机、边界值等），并使用 `TEST_LOOP` 施加时间/迭代压力。警惕恒定输入、退化输入，或编译器优化把激发行整体消除，导致被测单元实际"空转"。

### 2. golden 比对必须字节级 memcmp
比对必须使用 `memcmp` / `memcmp_or_fail`（或等价的逐字节比较），保证**位级一致**。浮点结果必须**可复现**：框架在 `sandstone_data.cpp` 中统一 quiet 化 SNaN，使 FP16/BF16 的 NaN 位型跨架构可匹配。因此禁止用含 NaN 的松散容差比较去掩盖 SDC，也禁止引入依赖未定义求值顺序或非确定归约的不可复现路径。

### 3. x86-64 非回归
ARM64 移植须为增量式：新架构代码放在 `#elif __aarch64__` 分支或按架构的 meson 守卫中；只有在确属共享时才可将 `#ifdef __x86_64__` 扩大为包含 `__aarch64__`。任何可能改变 x86-64 既有行为、或不当扩大架构宏条件的改动都应被指出。

### 4. 诚实性（未实现项必须跳过）
ARM64 上未实现的功能必须从 `test_init` 返回 `EXIT_SKIP`（-255，并先 `log_skip` 记录原因），原因文本格式为 `"to be implemented (placeholder): <缺失内容>"`。**严禁**以 `EXIT_SUCCESS` 或空操作让未实现的测试"假通过"——一个无实际检视逻辑却报告 pass 的测试是 bug。注意：`mce_check` 在 ARM64 上是真实 EDAC 后端的测试，必须真正通过，不得占位。

### 5. SVE / NEON 向量长度（VL）
向量代码不得对固定 VL 做硬编码假设。CI runner 上 SVE 的 VL=128，会**掩盖 512-bit 等高 VL 下的越界或位型差异**。评审时检查与 VL 相关的循环边界、谓词掩码与越界访问，特别关注"只在更高 VL 下才暴露"的错误，以及"在 CI 低 VL 下被掩盖"的误报。

### 6. 失败现场记录
发现不一致时，必须记录足以**离线复现**的现场信息：冷路径上的 bit dump、sum-bit 校验，以及触发失败的向量/输入数据；同时避免在高频热路径上做昂贵的打印或格式化。

## 三、误报校准（哪些情况不应报问题）

- **已知限制，非缺陷**：在 `-n 1` 单线程下运行，`eigen_svd_double` / `eigen_sparse` 等若出现 ULP 级差异属 Eigen 在大核数（192 CPU）下的已知限制，并非移植缺陷，不应作为本次改动引入的问题上报。
- **有意的架构差异**：x86-64 与 ARM64 之间存在**刻意**的行为差异（如平台 quirks：sysfs cluster_id 单调递增、无 cpufreq/thermal_zone 等），这是如实的平台特性，不是缺陷。
- **非激发相关改动**：纯 `grep`、文档（`docs/**`、`*.md`）、注释类改动若不涉及激发能力或比对逻辑，不应强行关联 SDC 议题上报。
- **框架/配置改动**：只要不改变 x86-64 行为、不削弱比对与激发，一般不构成 SDC 缺陷。
